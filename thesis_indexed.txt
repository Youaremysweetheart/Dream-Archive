012: 基于Spring Boot+Vue的梦境档案馆系统设计与实现
013: 摘  要
014: 梦境往往能反映出人们内心的活动和情绪，人们记录梦境的方式是口头传达或者备忘录，纸质的记录只能单一记录文本，对于信息保存、分类管理、内容检索和社区互动等方面存在一定局限，随着人工智能和互联网的发展，文本智能分析技术也为梦境内容自动处理与辅助理解提供了新的实现路径，为提高梦境记录的便捷性和信息管理的规范性，设计了基于Spring Boot + Vue的梦境档案馆系统，系统采用前后端分离架构，前端以Vue3构建交互界面，后端以Spring Boot搭建业务服务，MySQL实现数据持久化，结合Flask封装了深度学习模型，实现梦境的智能分析功能且返回分析结果，在经系统测试，该系统能够比较稳定地录入信息、查询、编辑、删除和展示，能够对梦境文本进行分类分析，功能满足设计要求规范，并设计了心理辅导室可供用户与AI助手进行心理辅导。本文设计的系统为梦境信息的数字化管理与文本智能分析提供了一种可行方案，为智能文本分析技术在垂直场景中的落地应用提供了参考。

017: Design and Implementation of a Dream Archive System Based on Spring Boot and Vue
018: ABSTRACT
019: Dreams often reflect people’s inner thoughts and emotions. Traditional dream recording methods (oral narration, memos, paper notes) only support plain text recording and have limitations in information storage, classification, retrieval and community interaction. With the advancement of AI and the Internet, intelligent text analysis technologies provide a new approach for automatic processing and assisted interpretation of dream content. To improve recording convenience and standardize information management, this paper designs a Dream Archive System based on Spring Boot and Vue. Adopting a front-end and back-end separation architecture, the system uses Vue 3 for the front-end interface, Spring Boot for back-end services, MySQL for data persistence, and Flask to encapsulate a deep learning model for intelligent dream text analysis. System tests show that the system stably realizes information entry, query, editing, deletion and display, and effectively conducts dream text classification, meeting design requirements. In addition, it integrates a psychological counseling room for users to communicate with an AI assistant. This system provides a feasible solution for digital management and intelligent analysis of dream information, and offers a reference for the application of intelligent text analysis in vertical scenarios.
020: Keywords: Spring Boot; Vue; deep learning; dream analysis; psychological counseling; dream archive management

067: 1  绪  论
068: 梦境能够反映出内心的活动和情绪，而梦境具有记忆极其脆弱的特点，过程中有着强烈的感官模拟，调动视觉听觉等器官让梦变得十分沉浸且逼真，当梦醒的时候情绪很容易被放大，常常能感觉到逻辑断层和失控扭曲，且样式五花八门，因此人们往往有记录和回顾梦境的需求，基于对梦境内容保存及其管理和分析方面，本文提出的Spring Boot系统借助于更加信息化的手段来应对此痛点。
069: 课题的研究背景和意义
070: 传统保存梦境的方式不限于口头复述、日记、备忘录等，此类方式虽然有记录文本的功能，但在长期保存、分类管理、检索和交流分享下存在明显的不足，随着信息化的发展和不断深入，用户对于梦境的要求也不仅仅是记录下来，而是希望能实现更加结构化的管理，实现多场景下的查询检索，交流分享，及时记录。人工智能和自然语言处理技术的飞速发展，让ai模型能够嵌入web系统，为梦境档案馆实现梦境文本分析提供了方向。因此，设计一个集成有核心记录梦境功能的，能够管理、分享与文本分析于一体的系统是有必要的。
071: 国内外研究现状
072: 从系统工程角度看，Spring Boot 在业务系统开发中的技术路径已经比较成熟，尤其适合需要快速构建接口、权限和数据管理能力的项目。相关研究与实践多出现在校园管理、绩效管理、供需匹配等场景[2][3][4][13]。这类系统的共同点是业务边界清晰、模块职责可拆分，和本文的梦境档案馆系统在工程组织方式上有较高相似度。前端方面，Vue 与 Vue 3 在中小型管理类系统中也形成了稳定实践，组件化开发与状态管理方式更利于页面迭代和交互维护[9][11][14]。
073: 在数据访问层建设方面，MyBatis 及 MyBatis Plus 的应用较为广泛，核心价值在于能兼顾开发效率与可维护性，适合需要较多业务查询和数据状态管理的系[15]。对本文项目来说，梦境内容、互动记录、后台治理数据都依赖稳定的数据持久化与查询组织，因此这一路线具有现实可行性。
074: 从内容智能方向看，文本分类、语义分析、推荐等技术已经在教育、服务平台和内容系统中持续落地[6][7][10]。但聚焦到“梦境档案管理+文本分析+心理辅导室交互”这一组合，现有公开研究和工程案例相对较少，尤其缺少从业务流程到模块联动都较完整的实现路径。很多系统要么停留在记录管理层，要么只展示模型分析结果，较少把记录、分析和后续对话衔接为一个连续过程。
075: 本文的工作重点正是在这个空白区域内做工程化实现：既保留常规 Web 系统应有的用户、内容和管理能力，也把文本分析和对话辅导放进同一业务闭环中。这样做不追求概念上的“全能”，而是尽量保证每一环都能在真实交互里跑通，并为后续优化留出清晰接口边界。
076: 1.3 研究目的和研究内容
077: 本文的研究目标是完成一个可稳定运行、可持续扩展、具备实际交互价值的梦境档案馆系统。系统不仅要支持基础的梦境记录与管理，还需要在用户完成发布后提供分析反馈与对话辅导，使“记录”不再是终点，而是后续理解流程的起点。
078: 围绕这一目标，本文在系统架构上采用前后端分离方案，后端基于 Spring Boot 承担业务服务、权限控制和数据管理，前端基于 Vue 3 实现页面交互与模块组织，MySQL 负责核心数据存储。为支持梦境文本分析，系统引入 Python Flask 模型服务，承担分析接口与结果返回；在对话能力上，集成 Dify 实现心理辅导室模块，使用户可以围绕具体梦境帖子进行上下文相关交流。
079: 在功能实现层面，本文完成了用户注册登录与个人信息管理、梦境发布编辑删除与公开/私密状态控制、评论点赞等互动功能，以及后台对用户、梦境和评论内容的治理能力。为了让智能能力可以长期维护，文本分析模块不仅支持自动分析，还考虑了重分析和批量补分析场景，降低模型迭代或历史数据补全时的维护成本。心理辅导室模块则围绕“今日梦境帖检测—房间进入—消息交互—历史切换”展开流程设计，尽量让对话入口与用户当次记录保持关联，避免出现与内容脱节的泛聊天体验。
080: 本文最后还将结合系统实现结果进行功能测试与回归验证，重点关注核心流程可达性、模块协同稳定性和基础可用性表现，确保系统在常见使用路径下能够正常运行。
081: 2  相关技术与理论基础
082: 2.1  Spring Boot 后端开发技术
083: Spring Boot 用自动配置和约定减少样板代码，适合快速搭 REST 接口。本系统服务端采用 Spring Boot，统一网关前缀为/api，与前端以 JSON 通信。安全上配合 Spring Security 与 JWT，区分普通用户与管理员。业务上负责用户、梦境、评论、点赞、分类与后台治理，并对外部能力做“衔接”：梦境分析由独立 Flask 服务提供 HTTP 接口，后端调用后回写；心理辅导室则通过 Dify 工作流生成回复，后端维护房间与消息。把分析与对话放在主工程之外，便于单独维护模型或调整工作流，主工程侧重稳定的路由、鉴权与数据落库。
084: 2.2  Vue 3 前端开发技术
085: 前端采用 Vue 3 单文件组件，配合 Pinia 管登录态与用户信息，Vue Router 管路由。除首页、发现、发布、详情、个人中心、后台等页面外，增加了心理辅导室入口页与按梦境帖维度的聊天页。界面组件以 Element Plus 为主，请求经 axios 封装，与 /api 与 Token 约定一致，减少联调时路径与鉴权上的混乱。
086: 2.3  MySQL 与 MyBatis 数据访问技术
087: 持久化使用 MySQL。数据访问采用 MyBatis（未使用 MyBatis-Plus），SQL 与 Mapper 映射可显式控制，在分析字段、辅导室表结构变化时改起来直接。dream 表扩展分析相关列；辅导室用 dream_room、dream_room_message 等表；若出话需要排队，可配合任务表异步处理，避免长请求占满 Web 线程。
088: 2.4 文本分析与辅导对话相关技术
089: 文本分析由 Flask 提供分析接口，后端在保存或重分析时调用，结果写回梦境记录。心理辅导室由 Dify 工作流支持，后端提交上下文并保存返回内容；前端以轮询等方式更新消息区。本系统把“辅导”定位为基于文本的轻量引导，不等同专业心理服务，话术与规则以工作流配置为准。
090: 2.5 本章小结
091: 本章说明了 Spring Boot、Vue 3、MySQL 与 MyBatis、Flask 与 Dify 在系统中的分工，为后文需求与总体设计做技术铺垫。

093: 3  系统需求分析
094: 3.1 系统可行性分析
095: 从技术条件看，前后端分离、Java 与 Vue 的教材和示例多，团队或个人在课程设计阶段能较快搭起原型；数据库使用 MySQL，数据模型与表关系容易用工具或脚本维护。模型分析端用 Python/Flask 单服务方式部署，与 Spring Boot 通过 HTTP 调用即可衔接；心理辅导室借助 Dify 等现成工作流，后端主要承担鉴权、会话与落库，不一定要把大模型全放进 Java 里训练与部署[2][9][14]。、
096: 3.2 功能需求分析
097: 在普通用户侧，系统要支撑账号的注册、登录与退出，以及个人资料、头像的维护。梦境作为核心数据，应支持按标题、正文、标签、情绪与做梦日期等维度发布、修改与删除，可配置公开或仅自己可见，并支持在正文中配图的保存与展示。在互动上，用户应对梦境发表评论与二级回复，可点赞与取消点赞，并能在个人主页或相应页面看到自己发表过的内容与会话。梦境经后台分析后，在详情中展示分析结论；分析失败或重跑时，还应有与系统既有接口一致的再分析、批量补分析等操作入口。心理辅导室是扩展能力：在具备当日梦境相关前提时，应能进入或复用与某一梦境帖关联的房间，在房内发送与查看历史消息，并在不同梦境帖对应会话间切换。若未满足进房条件或服务不可用，界面需有明确说明，避免用户空等。
098: 在管理员侧，需能够分页查看与检索用户、调整一般用户与管理员角色、对账号启用与禁用。梦境端应支持在后台按条件管理内容，并具备批量删除以减轻重复操作。对整体运行状况，应提供一定统计与看板信息，便于从治理角度看到用户量、内容量等概况。与上述能力并列，智能分析模块在业务上应覆盖梦境新建或内容更新后自动拉取分析、手动对单条重新分析、以及面向历史数据的批量补全分析，以减轻人工逐条点触。
099: 3.3 非功能需求分析
100: 在性能上，一般列表、详情、提交类请求应能在可接受时间内返回，不因单次操作明显阻塞界面；心理辅导室因存在轮询或异步出话，接口响应与刷新频率要约定在合理范围，以减轻服务器压力。在安全上，业务接口在登录后访问，用 JWT 等方式保持会话；涉及后台管理的操作需与管理员身份绑定；被禁用的用户不应以正常方式进入系统。在可维护性上，主业务、模型分析服务、对话工作流之间边界清楚，问题定位时可分别看日志与配置。在可扩展性上，后续若加强辅导策略、推荐或统计，应能在不推翻现有表结构的前提下增量迭代[7][10]；本阶段以完成既定模块与可演示的闭环为主，不预先承诺具体并发指标或压测数据。
101: 3.4 系统用例分析
102: 从用例角度，可将参与者大致分为普通用户与系统管理员两类。普通用户典型路径包括发布与管理梦境、浏览与互动、查看个人维度统计，在条件具备时经心理辅导室与 AI 围绕梦境文本互动。其主线可概括为在记录梦境后获得分析反馈，再进入辅助对话，形成与题目一致的“记录—分析—引导”链。管理员的用例则集中在用户与内容的治理、角色与状态控制、以及从统计上把握平台运行情况，不直接参与梦境文本与辅导话术的生成。

108: 4.1 系统总体架构设计
109: 在部署形态上，本系统可概括为浏览器访问 Vue 3 单页应用，经反向代理或直连，将 API 请求发往 Spring Boot 服务；后端配置中 context-path 为 /api，与前端 axios 的 baseURL 配合，形成带统一前缀的 REST 调用。数据持久化使用 MySQL 8.0；uploads 下头像与梦境图片以静态方式映射，供前端以 URL 访问。业务与展示以外，还连接两类外部/独立进程能力：一是本机或局域网内的 Flask 梦境分析服务（application.yml 中 sentiment.base-url，默认如 http://localhost:5000），在梦境发布、更新、手动/批量重分析时由 SentimentClient 以 HTTP 调用，结果回写 dream 表；二是 Dify 工作流（dify 节配置 base-url、api-key、工作流路径），在心理辅导室中由 DifyWorkflowClient 等组件调用，与 dream_room 的会话标识、消息与异步任务表协同。dream-room 的队列轮询间隔、批大小、最大重试在配置中可调，与后台异步消费任务、避免阻塞的设计一致。总体上看，是「前端 + Spring Boot 业务/协调 + MySQL + Flask 分析服务 + Dify 对话服务」的多进程结构。

119: 4.4 系统安全与权限设计
120: JWT 与公开接口方面，本系统在 WebMvcConfig 中注册 JwtAuthInterceptor，对除 CORS 预检外的请求做筛选：POST 中仅 user/login、user/register 免令牌；GET 中公开梦列表、热门、分类、以及符合正则的梦境详情、用户信息、按用户/梦境取评论等路径免令牌；uploads 等静态也放行。其余需携带 Authorization: Bearer 或约定头名 token，校验通过后在 request 中设置 currentUserId、currentUsername、currentUserRole。需登录的接口与拦截器白名单的缺口一旦不对齐，会出现 401，这属于实现阶段联调时重点核对的点。
121: Spring Security 当前配置中 anyRequest().permitAll()，不在过滤器链中按角色拦截业务 URL；BCrypt 的 PasswordEncoder 只负责密码存取算法，与接口鉴权是两条线。管理员能力集中在 AdminController：各方法在接口层调用 checkAdmin（基于请求属性中的 currentUserId 查库，核对 role 是否为 ADMIN），不通过前端的 isAdmin 自声明信任。
122: 用户状态在登录时校验，禁用账号在业务层直接拒绝登录。心理辅导室 DreamRoomController 在方法内读取 currentUserId，null 则 401，并在服务层按当前用户限制房间、消息，避免串号。
123: 前端 router.beforeEach 中：需登录的页面未登录则进登录页，需管理员的非管理员重定向到首页；这属于界面层防护，不能替代后端 401/管理员校验。

186: 7  总结与展望
187: 7.1 工作总结
188: 围绕「记录梦境、管理内容、做文本分析、在辅导室延续对话」这一条主线，本文完成了需求、总体设计、分模块实现和测试的毕设式闭环。系统采用前后端分离：Vue 3 负责页面与路由；Spring Boot 统一提供 /api 业务与鉴权，MySQL 落库，MyBatis 管映射；梦境分类与反馈由独立 Flask 服务推理并写回 dream 表；心理辅导室在落库和异步任务之外，用 Dify 工作流生成话轮，和 dream_room、消息、任务表配合。与单纯的「发帖—列表」型作业相比，本文在档案管理之上叠了智能分析和可进房的辅导模块，使同一梦境帖在分析后还能进入受控对话，服务链更完整。
189: 在工程细节上，项目把公开接口与需登录管理接口用 JWT 拦截和控制器内管理员校验拆开；梦境点赞、评论楼中楼、个人与后台、批量补分析等，都能在代码中对应到具体类与方法。测试上除了手工与联调，仓库内还有针对鉴权、403/401 的回归用例类，为结论提供一点可重复的依据。整体上，目标不是论文包装新技术名词，而是把能跑、能说清楚、能答辩的系统做扎实。
190: 7.2 存在的不足
191: 第一，数据与模型方面。分析结果依赖当前语料和配置下的分类器，样本多了之后标签分布、表述习惯都会变，泛化不能指望一次训练长期不变；本毕业设计没有把大规模打标、长时间对比实验写进正文的条件，不宜写具体准确率，只能定性说仍有上升空间。第二，工程与压测方面。日常演示下接口够用，但高并发、慢 SQL、大列表、Flask 与 Dify 同时排队时的表现，缺少系统压测报告；批量补分析接口在当前实现里对调用方约束不严，部署上仍要做隔离或补鉴权，这本身也是不足的一种表现。第三，辅导与产品方面。辅导室话术主要由工作流和队列策略决定，能做的是流程、状态、违规提示，离真正的个性化心理服务还有距离；「其他」类时的睡眠/压力弹窗仍是前端规则拼接，和模型深度未绑在一起。第四，数据表上虽预留 like_record 对评论的类型字段，评论点赞尚未做成接口，功能矩阵仍不齐。
192: 7.3 未来展望
193: 后续若继续迭代，模型侧可在标注规范统一的前提下扩语料、定验证集、记录版本与回滚，让「换模型」有据可查。 分析链上可把同步 HTTP 与已有任务表、消息队列打通，对长文或排队高峰做削峰，与 dream-room 的队列同一套监控思路。安全与运营上，批量分析、管理操作应走强鉴权与操作日志；后台统计可从现有 AdminController 的汇总再往前做细粒度、可视化。 辅导上在合规前提下可尝试轻量的情绪或主题趋势（例如按用户时间轴聚合分析标签仅为统计展示），不接医疗诊断。 前端上可将辅导室未使用的 /dream-room/history 与侧栏数据源二选一规范掉，少一层歧义。

210: 致  谢
211: 这写到这里的时候，屏幕上的光有点晃眼。
212: 好像这篇毕业设计终于快结束了。它不像一个任务被轻轻划掉，也不像游戏里跳出“通关成功”的提示，更像是某天晚上回头看，才发现自己已经拖着一身疲惫，绕过了不少坑，居然也慢慢走到了这里。
213: 一开始选这个题目的时候，其实没有想得特别远。只是觉得可以做，应该能做，慢慢做总能做出来。后来真的开始搭框架、写代码、调接口、改页面、补论文，才发现很多事情并不是“慢慢来”三个字就能解决的。页面会崩，接口会报错，数据库字段会对不上，论文写着写着也会突然卡住。明明只是一个小问题，却能让人盯着屏幕发很久的呆。
214: 有时候不是代码先乱了，是人先乱了。
215: 但好在，很多看起来过不去的地方，最后还是一点点过去了。今天改一点，明天补一点，错了就重来，乱了就重新理。那些当时像一团线一样缠在一起的问题，回头再看，也不过是被自己笨拙地、一点一点拆开了。
216: 首先要感谢我的指导老师。在整个毕业设计过程中，老师给了我很多耐心的指导和包容。其实我自己知道，我并不是一开始就思路清楚、进度稳定的人，很多内容都是边做边理解，边写边修改。老师一次次帮我把方向拉回来，提醒我哪里还不够清楚，哪里不能只是“能跑就行”。也正是在这个过程中，我慢慢明白，做系统不只是把功能堆出来，还要让结构清楚，让逻辑站得住，也让别人能够看明白。
217: 也感谢大学期间教过我的各位老师。以前上课的时候，很多知识像是飘在纸上的概念，数据库、计算机网络、操作系统、软件工程，听起来都有点远。可真正做项目时才发现，它们并没有离我很远，而是藏在一张表、一次请求、一个接口和一段逻辑里面。那些曾经觉得抽象的内容，最后都在项目里变成了具体的支撑。
218: 还要感谢身边的同学和朋友。毕业设计这段时间里，压力不只是来自论文和项目，还有实习、找工作，还有很多生活里说不清的情绪。有时候自己一个人想太多，就会越想越乱。和他们聊一聊，哪怕只是吐槽几句 Bug，随便说几句废话，也会觉得自己没有被完全困在原地。很多时候，人需要的也不一定是答案，只是旁边有人说一句：没事，先往下做。
219: 也感谢那些开源框架、技术文档和技术社区。这个系统不是我一个人凭空做出来的。从 Spring Boot 到 Vue，从 MySQL 到 Flask，从官方文档到技术博客，再到一次次搜索报错、翻解决方案，这些看不见的人和内容，都在我完成系统的过程中帮了我很多。很多 Bug 当时看起来像堵在路中间的黑影，解决之后才发现，也许只是一个没注意到的配置，一个写错的字段，或者一个自己还没理解透的细节。
220: 写到这里，也想感谢一个对我来说很重要的人。她在这段时间里给了我很多陪伴和鼓励，也让我的生活不只是论文、代码和压力。她的出现像一束柔和的光，不吵闹，却一直在。很多疲惫的时候，想到有人支持着我，想到那些一起走过的路、说过的话、经历过的日常，心里就会慢慢安定下来。
221: 她让我觉得，努力不只是为了完成一个项目，或者交上一篇论文，也是为了慢慢成为一个更可靠、更有担当的人。因为有她的陪伴，这段原本有些紧绷的毕业设计时光，也多了许多温暖的底色。
222: 当然，也要感谢我的家人。他们很多时候不会说太多，却一直在我身后。人在面对压力和不确定的时候，很容易怀疑自己，也怀疑以后到底会走到哪里。而家人的支持，就像一盏不太张扬的灯，不一定时时照在眼前，但只要回头，就知道它还在那里。

224: 未来还有很长的路要走。我知道自己还有很多不足，也还会遇到很多站不稳的时候。但还是希望以后的自己能慢慢稳一点，也更坚定一点。
